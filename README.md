# pdf-to-tts

财经研究内容到 TTS / 音频节目的 Prompt 工作区。

## 文件命名规则

采用：

```text
排序编号-能力名称.md
```

文件名描述“能力”，不描述版本。版本由文档内部和 Git 历史管理，避免出现 `final`、`new`、`v2-final` 等难以维护的文件名。

编号按 10 递增，便于未来在中间插入新能力：

```text
10-...
20-...
30-...
```

如需插入，可使用 `15-...`、`25-...`，无需整体重命名。

当某一能力已经不是单一 Prompt，而是会持续扩展出研究、规则、工作流、样本与反馈数据时，优先使用**编号目录**沉淀，而不是继续把所有内容挤在一个 Markdown 文件中。

## 当前 Prompt / 工作区

### `10-report-to-script.md`

**资料 / 研报 → 完整财经 TTS 文案**

用于一份或多份机构研报、行业报告、基金经理交流纪要等材料的分析、Debate Map 和最终节目文案生成。

### `20-xiaojunjun-honghao-editorial.md`

**洪灏原文 + 小君君主持人 → 双人音频节目**

用于保护作者原文，同时在关键节点加入主持人的解释、拆解与连接。

### `30-finance-audio-framing.md`

**已有财经音频 → 开场引导 + 播后分析总结**

用于已经存在音频、SRT 或逐字稿的场景。重点是找到最高信息张力，用开场制造认知缺口，并在原音频结束后完成事实、判断、条件、风险与验证变量的二次整理。

### `40-topic-selection/`

**PDF / 研报库存 → 视频选题筛选与排序**

用于整条生产链最上游的选题决策：从大量 PDF 中提炼候选命题，结合大众相关性、个人利益映射、反常识度、数字冲击力、预测具体度、权威性、证据可视化和多研报碰撞价值等维度评分，最终筛出 Top 5 候选题。

当前目录包含：

```text
40-topic-selection/
├── README.md
├── 10-reference-channel-patterns.md
├── 20-topic-scoring-model.md
└── 30-selection-workflow.md
```

后续真实发布后的 CTR、观看量、留存等反馈也应回流到该工作区，用自己的数据逐步修正选题模型。

## 职责原则

```text
40：先决定做什么、从什么角度做
10：从研究资料生产节目正文
20：把作者原文编辑成双人节目
30：给已经存在的财经音频增加前后包装
```

能力尽量单一，避免多个 Prompt 同时承担同一职责。

整体链路可以理解为：

```text
PDF 库
  ↓
40-topic-selection：选题
  ↓
10-report-to-script：正文
  ↓
TTS / 音频
  ↓
30-finance-audio-framing：开场与播后分析（按需）
  ↓
SRT / 视觉导演 / Thumbnail
```
