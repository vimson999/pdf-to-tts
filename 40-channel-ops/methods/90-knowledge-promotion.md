# 单集经验如何升级为根方法

> 状态：第一版

这个文件规定：什么时候可以把某一期的经验写进 `methods/`。

## 1. 三个层级

### Observation

只在单集里观察到。

例如：

> 这一期使用“真实研报首页 + 9 个字中文结论”，CTR 明显高于上一期。

它只能先写在：

```text
episodes/<episode>/80-performance-review.md
```

不能立刻变成频道 Rule。

### Pattern

同类现象在多集重复出现，并且不是明显由其他变量解释。

例如：

> 三期不同题材里，原始研报封皮都比泛财经图片 CTR 更高。

可以在相关 method 中标记为 Pattern。

### Rule

经过足够多场景验证，且知道适用边界。

例如：

> 在“机构研报解读”类视频中，真实原始报告作为可信度锚点通常应保留；但正文长段落不适合作为手机端 Thumbnail 主信息。

此时才正式进入根方法。

## 2. 升级时必须记录来源

每条被升级的方法，尽量注明：

```yaml
status: Pattern | Rule
derived_from:
  - S01E01-...
  - S01E04-...
  - S01E07-...
last_reviewed:
```

这样以后知道这条方法是怎么来的。

## 3. Rule 也可以降级

如果后续数据连续不支持旧 Rule：

```text
Rule
↓
Pattern / Hypothesis
↓
重新测试
```

不要为了保持文档稳定而保留失效经验。

## 4. 一次爆款不能自动产生 Rule

爆款可能来自：

- 题材；
- 热点时机；
- 推荐流量；
- 标题；
- 封皮；
- 频道增长；
- 偶然性。

所以必须尽量拆变量。

## 5. 每季结束做一次 Methods Review

第一季结束后建议统一检查：

- 哪些 Observation 从未复现；
- 哪些已经形成 Pattern；
- 哪些可以升级 Rule；
- 哪些旧 Rule 应该删除；
- 下一季最值得专门做哪些 A/B 测试。

最终目标是让 methods 越来越短、越来越准，而不是越积越厚。
