# 标题方法

> 状态：实验中
> 说明：当前内容是冷启动假设，必须由第一季真实数据验证。

## 1. 标题先服务命题，不替弱选题化妆

顺序必须是：

```text
核心问题 / 命题
    ↓
证据与限定条件
    ↓
标题角度
```

不要先想一个刺激标题，再回头寻找研报内容配合。

## 2. 第一版常用标题结构

### 2.1 结论型

```text
高盛：短期不必期待消费复苏
```

适合机构结论本身足够锋利时。

### 2.2 冲突型

```text
利率越来越低，人民币为什么反而升值？
```

适合反常识因果。

### 2.3 数字 / 预测型

```text
2027 上海房价或上涨 6%-12%，依据是什么？
```

适合报告有明确对象、时间和幅度时。

### 2.4 分歧型

```text
上海房价到底见底没有？三家机构为什么给出不同答案
```

重点是“同一个问题”，不是机构数量。

### 2.5 观点变化型

```text
三个月前还看空，为什么现在改口了？
```

适合同机构观点演变。

## 3. 每集至少生成三种标题角度

建议在 episode 中保留：

```yaml
title_candidates:
  conclusion:
  conflict:
  number_or_forecast:
  optional_debate:
  final:
  reason_selected:
```

## 4. 标题必须保留必要限定

如果研报说：

> 在基准情形下、满足 X 条件后，2027 年可能上涨……

标题不能无条件写成：

> 2027 一定暴涨。

传播性不能建立在删除关键前提上。

## 5. 第一季重点验证

- 机构名放前面 vs 问题放前面；
- 问号型 vs 结论型；
- 强数字是否显著提升 CTR；
- 长标题的信息增益是否抵得过阅读负担；
- 标题与 Thumbnail 是互补还是重复。

这些都先作为假设，不提前升级成 Rule。
