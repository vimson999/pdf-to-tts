# 内容形态选择：一份还是多份研报

> 状态：第一版

差异化不来自“每期必须多放几份 PDF”，而来自：

> **先确定问题，再选择最能回答问题的证据组合。**

## 1. `single-report`：单篇深拆

适合：

- 一份研报本身已有独家结论；
- 有强数字 / 强预测；
- 有专家访谈、调研或独特模型；
- 逻辑链完整；
- 其他报告没有明显新增价值。

优势：聚焦、清楚、证据链短。

风险：容易退化成“PDF 摘要”。

要求：必须先找到一个核心问题，而不是从第一页讲到最后一页。

## 2. `multi-report-synthesis`：多篇合流

多份材料结论并不一定冲突，但分别补齐问题的不同部分。

例如：

```text
高盛：解释汇率机制
大摩：解释居民资产行为
花旗：补充政策情景
```

最终目标是形成一条比单篇更完整的因果链。

风险：信息过多、没有主线。

判断标准：删掉其中一篇后，解释力是否明显下降？如果没有，就不应硬加。

## 3. `multi-report-debate`：多篇碰撞

适合：

- 同一问题有方向相反的结论；
- 目标值 / 时间点明显不同；
- 同一个数据被机构解释成不同含义。

视频重点不是罗列：

> 高盛说 A，大摩说 B。

而是解释：

> **为什么他们会不同意？决定结果的关键假设究竟是什么？**

优秀的碰撞视频最终应该能把分歧压缩成 1-3 个关键变量。

## 4. `view-evolution`：观点演变

比较同一家机构不同时点的观点：

```text
三个月前：A
新数据 / 新政策 / 新调查出现
现在：B
```

重点回答：

> **什么证据让机构改变了判断？**

这种结构天然有故事性，也方便验证机构过去的判断。

## 5. 形态决策顺序

```text
先确定视频问题
    ↓
找到最强主报告
    ↓
判断单篇是否已足够
    ↓
如果不足，再扫描相关报告
    ↓
选择 synthesis / debate / view-evolution
```

禁止：

```text
因为我们想做“多研报差异化”
所以强行塞 3-5 篇报告
```

## 6. 输出字段

每期选题确定时记录：

```yaml
format:
  single-report | multi-report-synthesis | multi-report-debate | view-evolution

primary_report:
supporting_reports:

why_this_format:
what_each_source_adds:
  - source:
    unique_value:
```
