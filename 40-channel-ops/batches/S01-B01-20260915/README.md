## Public Repo 留痕策略

原始导出包含 `fileId`、`topicId` 等来源系统资源标识。由于本仓库为公开仓库，**不把原始 JSON 原封不动提交到 Git**。

当前 `source-list.json` 保存：

- 原始数据指纹；
- 原始规模与状态统计；
- 规范化统计；
- 本轮选题真正使用的数据字段定义。

完整原始 JSON 应私下保留；Git 负责保存可公开的**决策轨迹**：批次指纹、清洗规则、候选题、评分、淘汰理由、最终单集资料清单和发布后数据。

这样既能复盘，又不会因为“留痕”把来源系统标识或受限资料暴露到公开仓库。

## 规范化

第一轮程序扫描只处理较确定的重复形式：

- 完全相同文件名；
- `_带图片_加密_1` 这类同报告副本后缀；
- 文件名末尾 `(1)` 副本标记。

结果：

```yaml
raw_items: 1347
normalized_items: 1334
collapsed_duplicate_rows: 13
```

语义近似但标题不同的报告暂不自动合并，避免误删真正不同版本；后续在主题聚类阶段处理。

## 本批次留痕链

```text
原始 JSON（私有保存）
  ↓  SHA-256 对应
source-list.json（公开批次清单）
  ↓
元数据初筛 / 主题聚类
  ↓
selection-result.md
  ↓
Top 候选读取 PDF 正文
  ↓
正式选题与内容形态决策
  ↓
episodes/S01E..
  ↓
发布数据回流
```

以后可以复盘的不只是“哪条视频表现好”，还包括：

- 当时有哪些资料可选；
- 为什么选中某个命题；
- 为什么淘汰其他候选；
- `downloadCount` 这类上游兴趣信号是否真的与 YouTube CTR / 观看量相关；
- `done / pending` 是否造成了可用性偏差；
- 选题评分模型与最终 CTR、留存、观看量之间是否存在稳定关系。
